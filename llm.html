LLM fundamentals

mock_llm(), tokens() — stateless, so the harness holds memory; free text, so output needs handling.

Two properties that shape every agent

Stateless

The model does not remember the previous turn. Every call receives the full message list. If the harness forgets to append a tool result, the model will not know the tool ran.

Free text out

The return value is a string — sometimes pure JSON, sometimes prose with a fenced block, sometimes a polite apology. Structure is a convention you enforce, not a type the API guarantees.

tokens() — the budget check

def tokens(msgs):
    return sum(len(m["content"]) for m in msgs) // 4   # ~4 chars/token

Real APIs charge by tokens and hard-fail past the context window. The mock does a cheap estimate and asserts early: 

assert tokens(msgs) < 8000, "context window exceeded"

You need this habit even with a mock: history only grows. A loop that appends tool results and errors will eventually fill any window unless you summarise, truncate, or stop.

mock_llm() — a teaching stand-in

def mock_llm(msgs, temperature=0):
    """Stand-in for a real model. Sees the whole history every call (no memory)."""
    assert tokens(msgs) < 8000, "context window exceeded"
    last = msgs[-1]
    if last["role"] == "user":
        return '{"action":"tool","name":"list_pantry","arguments":{}}'
    if last["role"] == "tool" and "milk" in last["content"]:
        bad = {"milk": 2, "yoghurt": 2, "rice": 1}      # first try ignores min basket
        return "Sure!\n```json\n" + json.dumps({"action": "order", "basket": bad}) + "\n```"
    if last["role"] == "error":
        good = {"milk": 6, "yoghurt": 6, "rice": 4, "eggs": 6}
        return json.dumps({"action": "order", "basket": good})
    return json.dumps({"action": "done", "summary": last["content"]})

It is deliberately awkward in the right places:

  • Stateless on purpose. It only looks at msgs, never at module globals for conversation state.
  • Free text on purpose. One reply is wrapped in Sure! and a markdown fence — so parse() must cope.
  • Wrong on purpose. The first basket is under £50, so you see a real reject → retry cycle.

Swap this for openai.chat.completions.create or any other API and keep parse / validate / run unchanged. That is the test of a clean architecture.

A short experiment

Call the mock twice with the same arguments and compare. Identical. Now append one more message and call again. Different answer — because the input changed, not because the model learned. 

a = mock_llm([{"role": "user", "content": "hello"}])
b = mock_llm([{"role": "user", "content": "hello"}])
assert a == b   # still stateless

Why this matters for agent design

Architectural consequence: anything you want the agent to “know” next turn must be explicitly written into the message list by the harness. Forgotten tool output is invisible. Dropped errors will be retried as if they never happened.
  • Keep history append-only during a task; summarise when you near the budget.
  • Never assume the model saw a side effect — append the observation.
  • Always parse before acting. Free text is a sketch, not an API response.

Exercises
