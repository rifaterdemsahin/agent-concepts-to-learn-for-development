⏳ Timeline of Events in Agent Systems

Numbered chronological sequence of every event from spec design to runtime self-correction and production monitoring.

📊 INFOGRAPHIC: The 12-Stage Agent Event Horizon Chronological Execution Order
🔢 Sequential Invariants

An agent cannot parse before model output, cannot act before validation, and cannot succeed without acceptance verification.

⚡ The Feedback Nexus

Events 7 and 8 form the critical self-correction pivot: a failed validation routes directly back to step 5 without human intervention.

🔄 The Outer Loop

Event 12 feeds back into Event 1: production logs reveal real-world edge cases that update the original SPEC dictionary.

📋 The 12 Numbered Events in Detail

1

🎯 Event 1: Define the Executable Specification Phase: Design

The developer defines business rules and boundary constraints in a single structured dictionary (SPEC in poc/bot.py). This dictionary is the single source of truth that will drive the prompt, the runtime validator, and the CI acceptance test. 

SPEC = {"goal": "restock low items", "min_basket_gbp": 50, "max_lines": 12,
        "low_stock_below": 2, "done_when": "order_placed"}
2

🔌 Event 2: Expose MCP Tool Capabilities Phase: Integration

Tools are registered with strict JSON schemas on the Model Context Protocol server. The agent loop inspects available tools via tools/list without knowing internal database details. 

TOOLS = {
  "list_pantry": {"description": "Current stock per item", "inputSchema": {"type": "object"}},
  "place_order": {"description": "Order {item: qty}", "inputSchema": {"type": "object"}}
}
3

📦 Event 3: Initialize Harness Context Memory Phase: Session Start

Because the LLM is completely stateless, the harness instantiates a working memory transcript array msgs and seeds it with the serialized SPEC prompt. 

msgs = [{"role": "user", "content": json.dumps(SPEC)}]
4

⏱️ Event 4: Pre-Flight Budget & Safety Audit Phase: Loop Guard

Before invoking the neural network, the harness conducts a sanity check on the token count (tokens(msgs) < 8000) and checks that current iteration has not exceeded max_steps. 

assert tokens(msgs) < 8000, "context window exceeded"
5

🧠 Event 5: Stochastic LLM Inference Phase: Reasoning

The complete transcript is sent to the LLM. The model computes next-token probability distributions across its transformer layers and outputs a text string containing conversational prose and an embedded JSON payload. 

raw = mock_llm(msgs)  # e.g. "Sure!\n```json\n{"action":"order", ...}\n```"
6

🔍 Event 6: Extraction & Syntax Parsing Phase: Parsing

The harness uses regular expressions to extract structured JSON from the conversational noise and decodes it into a Python dictionary. If extraction fails, a syntax error is recorded. 

def parse(text):
    m = re.search(r"\{.*\}", text, re.S)
    if not m: raise ValueError("no JSON found")
    return json.loads(m.group(0))
7

🛡️ Event 7: Deterministic Constraint Validation Phase: Safety Gate

The harness passes the parsed object through validate(). In poc/bot.py step 1, the model proposes a £10.20 basket. The validator detects that £10.20 < £50 minimum requirement and triggers a rejection. 

if basket_total(b) < SPEC['min_basket_gbp']:
    return f"basket £{basket_total(b)} is below minimum £{SPEC['min_basket_gbp']}"
8

🔄 Event 8: Closed-Loop Error Feedback & Retry Phase: Self-Correction

Crucial cybernetic pivot: instead of terminating, the harness appends the rejection message as {"role": "error", "content": err} into msgs and proceeds to the next loop iteration. The model reads the error and adjusts its basket on the next step. 

print(f"[{step}] REJECTED: {err}")
msgs.append({"role": "error", "content": err})
continue
9

🛠️ Event 9: Protocol Tool Execution Phase: Actuation

Once an output passes all validation gates, the harness calls the MCP server using standard JSON-RPC protocol (tools/call with name and arguments). 

res = mcp_handle({"method": "tools/call", "params": {"name": "place_order", "arguments": {"basket": out["basket"]}}})
10

👁️ Event 10: State Ingestion & Observation Update Phase: Observation

The result returned by the tool ({"status": "order_placed", "total": 50.6}) is appended to msgs with role: tool. The agent's working memory now records that the order succeeded. 

msgs.append({"role": "tool", "content": json.dumps(res["content"])})
11

🏁 Event 11: Termination & Acceptance Assertion Phase: Verification

The loop detects action: done matching SPEC["done_when"]. The test harness verifies the final state with assert run(). CI/CD passes. 

assert run(), "acceptance test failed: bot never reached done_when"
print("acceptance test passed ->", SPEC["done_when"])
12

📊 Event 12: Production Telemetry & Specification Iteration Phase: Evolution

In production, telemetry tracks reject rates, step counts, and token costs. When unexpected edge cases appear (e.g. out-of-stock items, price fluctuations), they are formulated into new constraints in SPEC, restarting the cycle at Event 1. 

# Telemetry insight: "Eggs out of stock" -> Add constraint: "substitute_allowed: true"
